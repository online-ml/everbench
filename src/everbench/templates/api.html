everbench / API

The API lets you upload a predictor, remove it, backtest it against a task archive, and inspect the Python environment.

Authentication and model signatures

EVERBENCH_API_KEY is the required deployment-level password for every documented API route. Send its value as X-API-Key. It prevents unauthorised people from deleting models, running backtests, or inspecting the environment; it is unrelated to the model itself. /api/health remains unauthenticated solely for Railway health checks.

Every uploaded pickle must also carry an HMAC signature in X-Everbench-Artifact-Signature. This is a separate trust check: pickle files can execute Python code when loaded, so Everbench only loads models signed with the private EVERBENCH_MODEL_SIGNING_KEY. To request the signing key, email maxhalford25@gmail.com, set it as EVERBENCH_MODEL_SIGNING_KEY in your local environment, then run uv run everbench sign-model model.pkl. Treat it as a secret: anyone holding it can submit a model that the server will unpickle.

Upload a model

POST /api/tasks/<task>/models
Accepts multipart form data: a model pickle file, model_id, owner, and class_definition. The class definition is stored with the artifact and shown when someone clicks the model in the leaderboard. An optional metadata field contains a JSON object.

Everbench uses cloudpickle to serialize model artifacts. This means an adapter class defined in your own upload module—such as one that calls Lift Wing—can travel with the pickle instead of being installed as trusted server code. A pickle must provide either predict_one(features), predict_proba_one(features), or predict_event(event_id, features). learn_one(features, y) is optional: scoring-only predictors are evaluated normally but do not receive in-place updates. Before registration, Everbench verifies the HMAC signature, checks this protocol, deep-copies the model, and replays the five newest labelled archived examples. Uploads require at least five such examples.

uv run everbench sign-model model.pkl
curl -X POST http://127.0.0.1:8000/api/tasks/dummy/models \
  -H 'X-API-Key: …' \
  -H 'X-Everbench-Artifact-Signature: …' \
  -F 'model=@model.pkl' \
  -F 'model_id=my-model' \
  -F 'owner=your-name' \
  -F 'class_definition=<your_model.py'

Lift Wing revert risk

Lift Wing is uploaded exactly like every other model. The example adapter is scoring-only: it uses each wiki revision ID and returns Lift Wing’s reversion probability. Build its pickle locally, sign it, then upload it to wiki-leftwing with the source file as class_definition.

uv run python tasks/liftwing/liftwing_revertrisk.py --user-agent 'your-tool (you@example.com)'
uv run everbench sign-model liftwing.pkl
# Upload with the same multipart route shown above.

Delete a model

DELETE /api/tasks/<task>/models/<model> deactivates a model without removing its historical state.

Backtest a model

POST /api/tasks/<task>/models/<model>/backtest replays one archive from the model’s original upload. It does not change the live model or its leaderboard metrics.

POST /api/tasks/dummy/models/my-model/backtest
{"archive_sha256":"the SHA-256 in the archive download link on the task page"}

Python environment

GET /api/environment returns the Python version and every installed package with its version, so you can build and pickle a compatible model.
